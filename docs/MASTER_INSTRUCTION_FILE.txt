1.2 THE "PASS-THROUGH" COD MODEL (CRITICAL TO UNDERSTAND)
---------------------------------------------------------
  1. A BUSINESS CLIENT (the B2B customer, e.g. an e-commerce seller) sells
     physical products to end-customers (often COD — Cash On Delivery).
  2. The client hands shipments to Maa Sharda Enterprises, which books them
     on DELHIVERY. Delhivery's own invoice/PDF shows the PRODUCT VALUE
     (e.g. CLOTHS x 1 @ INR 2000) and end-customer details.
  3. Maa Sharda Enterprises bills ONLY the Client — and ONLY for the
     SHIPPING SERVICE (freight) + GST. The product's value and the COD
     amount belong to the Client's transaction with its end-customer —
     they are PASS-THROUGH and must NEVER appear on our invoice.

1.3 CORE OBJECTIVE OF THE SYSTEM
--------------------------------
  Generate a legally compliant B2B "TAX INVOICE" (PDF + HTML) from:
    - Client details (name, address, GSTIN)
    - Base shipping charge (taxable value, Rs)
    - Shipment metadata (AWB, consignee name, client order ID, pincodes,
      weight)
  The system computes GST automatically, formats the number to words, and
  emits a pixel-perfect US Letter PDF.

SECTION 2: STRICT GST COMPLIANCE RULES (ZERO EXCEPTIONS)
================================================================================

RULE G1 — ABSOLUTE EXCLUSION LIST (NEVER PRINT THESE ANYWHERE)
--------------------------------------------------------------
  [X] Product Name / Item Description (e.g. "CLOTHS")
  [X] Product Value / Declared Value (e.g. INR 2000)
  [X] COD Amount (total cash collected from end-customer)
  [X] Quantity / Qty column
  REASON: The invoice bills a SERVICE (freight), not goods. Product/COD
  data belongs to the Client<->End-Customer relationship. Mentioning goods
  on a service invoice misrepresents the supply and breaks GST compliance.

RULE G2 — SERVICE IDENTIFICATION (MANDATORY ON EVERY INVOICE)
-------------------------------------------------------------
  Service Description (static) : "Courier & Logistics Services"
  SAC Code (static)            : 9968
    * Must be permanently visible, RIGHT-ALIGNED on the SAME horizontal
      row as Service Description (see Section 3.3).

RULE G3 — GST CALCULATION LOGIC (18% ON BASE FREIGHT)
-----------------------------------------------------
  Let base = Base Shipping Charge (Taxable Value), rounded 2dp half-up.
  Determine client state code from the FIRST 2 DIGITS OF THE CLIENT'S
  GSTIN (fallback: client_state name lookup).

  IF client state code == 23 (MP, same as supplier) -> INTRA-STATE:
      Print TWO rows: "Add: CGST @ 9%" AND "Add: SGST @ 9%"
      cgst = sgst = round(base x 0.09)

  IF client state code != 23 (or unknown/other) -> INTER-STATE:
      Print ONE row: "Add: IGST @ 18%"
      igst = round(base x 0.18)

  Total Invoice Amount = base + cgst + sgst + igst  (never anything else)
  Amount in Words (Indian numbering: Crore/Lakh/Thousand) must follow the
  total, e.g. "One Thousand One Hundred Eighty Rupees Only".

RULE G4 — PARTY DETAILS
-----------------------
  * Supplier block = HARDCODED (name/address/GSTIN from Section 1.1).
    Never extract supplier details from any PDF.
  * Billed To block = the BUSINESS CLIENT (dynamic: name, address, GSTIN,
    state).
  * The CONSIGNEE (end-customer name) must NEVER appear in the BILLED TO
    block. It appears only inside the Service & Shipment Details box as
    reconciliation data.

RULE G5 — DOCUMENT IDENTIFICATION
---------------------------------
  Title         : "TAX INVOICE"
  Invoice Number: SEQUENTIAL, FY-aware — format MSE/<FY>/####
                  e.g. MSE/2026-27/0001. Indian fiscal year runs
                  APRIL->MARCH (a date in Feb 2027 belongs to FY 2026-27).
                  Counter persisted in a text file
                  (generated/gst_invoice_counter.txt, lines "FY: count").
  Invoice Date  : YYYY-MM-DD only — TIME IS NEVER PRINTED (existing
                  clean_date_string() helper strips it).

RULE G6 — GSTIN VALIDATION (WARN, DON'T BLOCK)
----------------------------------------------
  Regex : ^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$
  CLI prints warnings for missing/invalid client GSTIN or placeholder
  supplier GSTIN. B2B invoices should carry the client's GSTIN (needed
  for ITC).

4.3 KEY IMPLEMENTATION NOTES (REPORTLAB SPECIFICS)
--------------------------------------------------
  * SimpleDocTemplate(path, pagesize=letter, margins=36), platypus story.
  * Right alignment: ParagraphStyle(..., alignment=2) and/or TableStyle
    ("ALIGN", (col,row), (col,row), "RIGHT").
  * !!! SPAN TRAP (CAUSED A REAL BUG) !!!
    ("SPAN", (0,r),(1,r)) indexes are ROW-POSITIONAL. Adding a row shifts
    every later row — every SPAN/ALIGN/padding directive must be
    re-indexed. Approved final indexes for the svc table:
    SPAN rows 0 and 4; ALIGN RIGHT at (1,1) and (1,3).
  * !!! WIDTH TRAP (CAUSED A REAL BUG) !!!
    A nested table inside a padded box must use
    (box_width - horizontal_padding) = 540 - 30 = 510. Oversized inner
    tables silently overflow the box border (~15pt past it).
  * Money rounding: Decimal.quantize(0.01, ROUND_HALF_UP) — never float
    math.
  * Sequential numbering writes back to the counter file — reset
    generated/gst_invoice_counter.txt to restart a FY sequence (e.g.
    after tests).

4.5 MANDATORY VERIFICATION PROTOCOL (RUN AFTER ANY LAYOUT CHANGE)
-----------------------------------------------------------------
  Using pdfplumber on the output PDF:
  1. FORBIDDEN-WORD SCAN (G1): none of "Item Description, Qty, Quantity,
     COD, CLOTH, Product" may appear in extracted text.
  2. SAC ROW GEOMETRY: "Service" and "SAC" words share the same top
     (+/-2pt); "9968" ends at x1 ~ 561 (box inner-right); Service label
     starts x ~ 51.
  3. OVERFLOW SCAN: no word on the page may have x1 > 577 (right margin).
  4. ORDER OF ROWS: AWB < Consignee/OrderID < Service/SAC < Pincodes.
  5. BILLED TO ISOLATION: consignee name must NOT appear between the
     "BILLED TO" and "SERVICE &" text anchors.
  6. TAX MATH: same-state -> CGST & SGST rows present, IGST absent (and
     vice versa); Total = base + taxes; words string present.
  7. Single page, size 612x792, exactly ONE image (small Delhivery icon).
